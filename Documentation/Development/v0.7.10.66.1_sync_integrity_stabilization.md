# v0.7.10.66.1 — Sync routing and integrity stabilization

## Scope

This is a corrective overlay on v0.7.10.66.0. It does not change fantasy scoring, Fantrax normalization, editorial composition, or Studio activity display semantics.

## Findings

Studio already maps Sync League to `Tools/sync_league.py`, which calls `Athena.sync.sync()`. The missing protection was end-to-end correctness: earlier required-stage validators could accept existing artifacts without showing that the current invocation regenerated them. Studio also treated an already-open Scout port as evidence that a valid patched Scout was running.

## Changes

- Required Fantrax core steps now verify that canonical files actually change their filesystem metadata during the current step, rather than accepting stale prior-run artifacts. This is an execution freshness check, not a claim that the content itself necessarily changes.
- League settings, profile, active workspace league ID, raw league-history ID, and season are cross-checked where available. A mismatch fails the sync.
- `Tools/sync_league.py` refuses incompatible provider/mode and refuses `ok: true` when required stages were omitted, skipped, or failed validation.
- Studio's Verify Build registry includes `Tests.test_sync_integrity_0710661` as a release-critical gate.
- Studio no longer silently opens an unverified existing Scout listener on Launch Scout. It directs the operator to Reload Build. A forced launch aborts if stop did not clear the configured listener ports, and a child that exits is not mistaken for a successful launch merely because another process owns the port.

## Acceptance and limitations

Offline tests validate the negative cases (stale file, absent file, mismatched league, skipped required steps, unexpected workspace, occupied listener source behavior) and the positive completion contract. There is **no authenticated Fantrax live synchronization or Windows Studio GUI test in this environment**. After installing, restart Studio, use Reload Build to ensure the Scout listener is clean, run Verify Build, then Sync League. Inspect the saved Studio command log for `ok`, `failed_step`, `completed_steps`, and `warnings`.

Optional modules such as transactions retain existing graceful degradation semantics. This build intentionally does not claim full optional capability completeness or repair unresolved period scoring attribution.

Note: the earlier 363-turn Scout export does not include the Studio Sync League execution log; the exact reported sync failure stage could not be reproduced from that export. This patch closes demonstrable false-success and runtime-ownership gaps without claiming an unobserved root cause.
