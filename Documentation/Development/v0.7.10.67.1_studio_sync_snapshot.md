# v0.7.10.67.1 — Studio League Sync Snapshot Restoration

## Problem
Studio's `_run_command` captures full subprocess output to a log, but `_command_summary` deliberately returns only `[PASS]` and the log path for every successful command. As a result, the canonical `Tools/sync_league.py` JSON includes league-wide operational metrics but the Studio surface hides them. League Sync is a workspace acquisition/status operation, **not** Scout's weekly league editorial analysis.

## Fix
- Extend Athena's sync summary from canonical `league_profile.json`, `league_settings.json`, and `player_master.json` with league name, season, league ID, team count and player count. The existing canonical transaction, asset movement, manager, liquidity and readiness metrics remain unchanged. No extra provider acquisition or period-specific analysis is added.
- Restore a compact operator-facing league-wide snapshot specifically for Studio's successful `Sync League` operation, while retaining raw JSON in Studio's command log.
- Never display a cached successful snapshot on failed sync. Unknown values appear as unavailable. All other Studio commands preserve their existing compact status.

## Acceptance
From Studio, run **Sync League** with the configured Fantrax fantasy workspace. After a verified successful run, the console should show `League-wide sync snapshot (not a weekly report)` followed by configured teams, players, canonical transactions, asset movements, manager analysis, market liquidity, knowledge readiness and warning count. This is a pipeline state snapshot, not a weekly standings report. Run Scout's `Summarize Week 7 of the JHLPAA` separately to confirm editorial routing remains independent.

A sync failure remains a failure; inspect the named full-output log. This overlay does not establish that live Fantrax authentication and acquisition succeed on the user's Windows host.
