# AthenaEngine v0.7.10.58.0 — Historical Identity Universe & Reconciliation

## Objective

Resolve current and historical Fantrax players through **one canonical identity resolver**, without team-specific IDs, manual NHL assignments, lineup guesses, or score adjustments. Existing v57 multi-period audit remains the acceptance oracle.

## Changes

1. The identity-population builder reads the union of current Fantrax player master IDs, verified archived period roster IDs, named scorer metadata in raw Fantrax transaction records, and **all** prior named identity-map entries (including `review` and `unresolved`, not only prior `resolved`). It does not infer historical roster membership or scoring from transactions.
2. Missing historical roster names are not guessed: they persist as unresolved IDs with `missing_historical_fantrax_name` and specific source provenance. Malformed archived rosters are rejected as sources.
3. NHL name collisions now use a uniquely matching position family (`LW` ↔ NHL `L`, `RW` ↔ NHL `R`, etc.) as a strict discriminator. Two candidates with the same full name and position remain ambiguous. Team matching alone is no longer allowed to select between distinct same-name NHL IDs.
4. Permanent previously verified Fantrax ↔ NHL IDs survive loss of a skater from a later NHL source, but current contrary candidate IDs, conflicting Fantrax name evidence, or a mismatched new verified NHL ID prevent automatic carry-forward.
5. The period audit inquiry enriches any still-unresolved ACTIVE Fantrax ID with its canonical name, map status, match method and provenance, **without changing** official totals or NHL attribution. Scout renders these explanations in the multi-period narrative.
6. The identity coverage artifact is emitted beside the identity map, including historical ACTIVE coverage after eligible players are re-resolved. The period-production cache from v55 continues to invalidate when resolved crosswalk IDs change; the v56/v57 scoring audits run after the identity refresh.

## Studio procedure

1. Extract over the canonical `AthenaEngine` folder **after v0.7.10.57.0**. No Raw or Output data is shipped.
2. **Reload Build → Verify → Sync League**. Confirm player-identity validator, historical-roster acquisition and historical-scoring-audit optional stages.
3. Ask Scout: **“Reconcile JHLPAA scoring for Weeks 2 and 3. For each of the 14 teams, compare Fantrax points with ACTIVE NHL points, list unresolved player names and IDs, reserve exclusions, and exact point differences. Then produce Week 3 editorial commentary from verified evidence.”**
4. Confirm `048x9`, `03yh8`, `05k8c`, `03wor` are resolved in `Output/player_identity_map.json`. Expected associated Week 2/3 numeric results must be recalculated from evidence; **do not fabricate 14/14**.
5. Inspect `Output/player_identity_coverage.json` and `Output/PeriodScoringAudit/sync_manifest.json` plus debug/session logs. If differences remain with all identities resolved, investigate exact lineup timing/provider scoring rather than forcing a match.
6. Test an unrelated same-name + different-position pair and a same-name + same-position pair. The first may resolve with unique position; the latter must remain ambiguous.
