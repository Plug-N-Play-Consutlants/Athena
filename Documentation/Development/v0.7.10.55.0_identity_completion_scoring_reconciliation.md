# AthenaEngine v0.7.10.55.0 — Identity Completion & Scoring Reconciliation

## Root cause and correction

- `Athena.sync` previously refreshed `Output/player_master.json` but did not rebuild the NHL identity map. The current roster contained 287 records; the saved identity map had only 281 total entries, including retained former roster identities. The last observed live historical-period scoring reconciliation covered 2/14 teams.
- The cached `Raw/nhl_skater_summary.json` already contained Rasmus Andersson, Lawson Crouse, Josh Manson, and Nikita Zadorov. Three were missing from `Output/player_identity_map.json` and Andersson was incorrectly marked `review` for a changed/multi-club NHL affiliation.
- Full-name evidence is independent of a player's current NHL club. Unique exact-name candidates now resolve despite NHL team changes. Multiple same-name candidates remain ambiguous; the resolver prevents the same NHL ID from being assigned to two Fantrax IDs.
- The standard Fantrax sync now rebuilds the map *after* rebuilding the current player master. This is a Knowledge stage, not a second fantasy scoring implementation.
- A new optional Fetch stage obtains current-season official NHL skater IDs to supplement rather than overwrite the prior season's NHL summary. It records a bounded warning and preserves cached candidate records when the NHL API is unavailable.
- Verified prior mappings are retained for identical Fantrax player IDs and stable names; historical players no longer on the current roster remain mapped. Contradictions or duplicate NHL IDs are not silently resolved.
- Period NHL scoring caches now include a fingerprint of the **resolved Fantrax↔NHL identity graph**, in addition to existing roster/period/window fingerprints. Repaired mappings force a new player production aggregation rather than trusting stale 23-point production.
