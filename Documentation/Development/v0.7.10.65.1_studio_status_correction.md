# v0.7.10.65.1 — Studio activity status correction

- Restores **Ready** as the idle Studio task state.
- Makes **Verifying build** visible immediately on starting Verify Build and updates its current check on the Tk event queue.
- Returns the task indicator to **Ready** after PASS, FAIL, CANCELLED, or ERROR; a separate `Last verification` line retains the actual result. Console and command logs still record each outcome.
- Separates Scout service availability from the Studio task indicator. Refreshing status no longer overwrites a running verification with the Scout service state.
- This is a presentation fix only; no validation command, result classification, engine route, scorer, Scout launcher or Studio startup flow is changed.

Run `python -m unittest Tests.test_studio_activity_status_0710651` from the repository root, followed by Studio's Verify Build on Windows. While running, it must show Verifying build (N/17); after it finishes, the status must read Ready and the separate last-verification line must say PASS or FAIL.
