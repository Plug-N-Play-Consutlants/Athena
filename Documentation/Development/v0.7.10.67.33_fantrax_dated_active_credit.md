# v0.7.10.67.33 — Fantrax explicitly dated active scoring contract

## Prior research and independent source

Before implementation, reviewed existing Athena `Knowledge/Integrations/Fantrax/RESEARCH_INDEX.md`, `Knowledge/Fantrax/API_Research_2026-10-14.md`, provider source, and `meisnate12/FantraxAPI` `fantraxapi/api.py` `get_live_scoring_stats` (GitHub commit `2252faff5cb96495908e1a31db08eef24280ad5d`).

The upstream request is an `fxpa/req` `getLiveScoringStats` message using `date=YYYY-MM-DD`, `newView=True`, `period="1"`, `playerViewType="1"`, `sppId="-1"`, `viewType="1"`. Upstream `League.live_scores` reads `scorerMap` and `statsPerTeam.allTeamsStats[teamId].ACTIVE.statsMap[scorerId].object1`; upstream date validation uses its league scoring-calendar model. These are **source-reviewed** contracts, not live JHLPAA-verified semantics.

## Implementation / acceptance

- Add a read-only, explicit-date `FantraxClient.get_live_scoring_stats()` using the documented request. No implicit current date, historical date guessing or per-period mapping.
- Add aggregate-only `probe_daily_credit` and `_daily_credit_shape` to existing `Tools/fantrax_period_probe.py`. No names, IDs, points or team identifiers emitted; no authenticated raw response is persisted. Bounded traversal and duplicate/missing-ID checks.
- Existing Studio Developer Mode → Fantrax Diagnostics → Player-period contract gets an **optional daily date** entry in the same dialog, using the existing Run Probe / View Report / Copy Report controls. Blank date preserves the old period test. No new permanent Studio buttons.
- Independent report schema `athena.fantrax_daily_credit_probe.v1`, tagged `response_received_unverified` until actual date semantics, period window, historical lineup and reconciled team totals are confirmed.

## Protection gates

- `verified_period_credit=false`, `ledger_written=false`, `credit_eligible=false` unconditionally.
- One date per request; no bulk scraping, authorization bypass or speculative history inference.
- Team totals and matchup lists may be absent or structured differently in a total-points league; do not assume H2H semantics.
- Next: run a date inside a known JHLPAA period, inspect safe structure, cross-check period calendar, reconcile player sums and team totals. Only then consider canonical scoring ledger acquisition.
