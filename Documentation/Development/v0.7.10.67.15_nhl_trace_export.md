# v0.7.10.67.15 — NHL source trace diagnostic export

## Purpose

Studio's **Export Diagnostics** previously collected `Logs/` records and select
`Reports/` files, but not the sanitized NHL source traces generated by
`Athena/Investigation/nhl_period_production.py` under
`Output/PeriodScoringAudit/nhl_source_traces/<league>/<season>/period_NNN.json`.
Consequently the v67.14 source-trace failure was referenced in command output
but absent from the exported diagnostics package.

## Implementation

`Tools/athena_studio.py` now collects metadata-only source traces as part of
**Export Diagnostics**. Each is stored in the archive at its natural relative
path under `Output/PeriodScoringAudit/nhl_source_traces/`.

Rather than copying arbitrary JSON, the exporter checks the expected trace
schema and writes an allowlisted representation containing the period, season,
error type, and per-request pagination counts/flags. It intentionally excludes
request URLs, filters, headers, access tokens, cookies, raw player IDs, and
raw player/game records. Oversized or malformed traces are not included and
appear as errors in the export manifest. The manifest reports
`nhl_source_trace_count`, and Studio displays that count after export.

There are no new controls or PowerShell steps; the existing **Export Diagnostics**
button is used. **Refresh & Reconcile Evidence** remains separate.

## Acceptance

After a failed historical acquisition, click **Export Diagnostics** in Studio.
The resulting ZIP should contain entries such as:

`Output/PeriodScoringAudit/nhl_source_traces/<league>/<season>/period_006.json`

with equivalent files for periods 7 and 8. The diagnostic metadata can then
identify returned page sizes and repetitive offsets without revealing raw data.

The NHL acquisition algorithm itself is unchanged in this release.
