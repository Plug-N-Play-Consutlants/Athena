# AthenaEngine v0.7.10.67.20 — Transaction Asset Integrity

## Change boundary

- Preserves Fantrax draft-pick payloads as typed `draft_pick` assets, retaining year, round, originating team label, transaction source, and observed transfer direction.
- Maintains the transaction event timestamp separate from the roster-effective scoring period in the canonical master and transaction history timeline.
- Makes event-period intelligence expose typed asset movements; the existing Scout multi-period publication already renders the `received` asset names, including draft picks.
- Existing 14-player November 18 chronology behavior is preserved. No provider scoring calculation or scoring-audit dependency was added.
- Does not invent stable pick IDs or assume current draft ownership is the historical transaction ledger.

## Validation

37 relevant tests passed, including Fantrax transaction normalizer fixtures, trade chronology, cross-period analysis, routing and provider-scoring tests. The observed archived Bobby Orr–Bubba trade now carries Owen Power, Tom Wilson and a 2028 Round 3 pick originating with Bubba’s Bruisers, transferred to Bobby Orr.

## Installation / acceptance

Apply the cumulative overlay to the AthenaEngine project root; restart Scout. Rebuild/reload canonical transaction master and knowledge history through the existing Fantrax data workflow before testing the narrative against live output. Historical output files written by earlier builds do not magically acquire the previously lost pick. Validate the narrative in Scout and confirm the normalized archive contains all three assets.

## Boundary / risks

- Draft picks without explicit `draftPickDisplayParts` are not inferred.
- Calendar classification requires a verified scoring calendar or other established provenance; the provider `season_week` represents roster-effective timing and is never silently promoted to a verified approval date.
- This overlay does not implement the pending verified per-player/per-period fantasy point acquisition.
