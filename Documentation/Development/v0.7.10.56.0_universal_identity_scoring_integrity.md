# AthenaEngine 0.7.10.56.0 — Universal Player Identity & Historical Scoring Integrity

**Status:** Local build PASS (115 pytest tests + 36 unittest subtests). Studio/Fantrax live acceptance outstanding.

**Installation:** This is a scoped overlay for an installation already at v0.7.10.55.0. Archive entries begin under `AthenaEngine/` so extract into the parent directory containing that folder (usually `F:\Development\`), allowing replacement of existing files. Alternatively copy the overlay's `AthenaEngine/` contents into the existing repository folder. Never extract an extra nested `AthenaEngine` folder into the repository.

**Workflow:** Reload Build → Verify → Sync League → Scout inquiry → inspect Scout report and `Output/PeriodScoringAudit` manifest. Sync audit is optional/non-blocking; verify any acquisition gaps rather than treating an optional step's failure as zero points.

## What changed (engine-wide)

1. **Expanded reusable NHL identity evidence:** The NHL candidate refresh performed from the normal sync script acquires current plus two prior NHL seasons, validating all source periods and refusing incomplete/mixed-season response data. Persistent NHL IDs deduplicate seasons, with the latest recorded affiliation preferred. The source is retained on failure. Explicit fixture calls to `run(... seasons_back=0)` continue to support single-season testing.
2. **Historical player-name aliases:** The identity resolver retains multiple names observed for one permanent NHL ID. A unique historical name can resolve even after a public-name or transliteration change. Two NHL players sharing a name remain ambiguous. Prior verified Fantrax/NHL links remain protected against conflicting evidence; a change of NHL club never changes permanent identity.
3. **Generalized identity completeness inventory:** `Output/player_identity_coverage.json` indexes current identities and valid archived roster periods. It records every unidentified ACTIVE player ID and the supported reason. No NHL debut, fantasy team ownership or period credit is inferred for a prospect without an authoritative NHL match.
4. **Explicit per-player scoring exceptions:** Every team reconciliation includes unexplained point differences, ACTIVE IDs missing identity evidence, resolved players with no NHL game rows, and NHL points earned by RESERVE / INJURED_RESERVE skaters **excluded** from the eligible subtotal. Numeric equality is distinguished from complete identity coverage and from verified game-effective Fantrax credit.
5. **Automatic recent-history audit:** Optional final Sync League step audits up to four most recent *elapsed* Fantrax periods with verified timezone-aware boundaries, canonical cumulative standings and baseline, validated historical rosters, and official NHL game G+A. It writes `Output/PeriodScoringAudit/sync_manifest.json` and `Output/PeriodScoringAudit/<league>/<season>/period_NNN.json`. Missing authentication, prior standings, source coverage or precise provider instants is an explicit exception, not a fabricated match. Scout queries also persist the attribution for the selected period, including older periods.
6. **Traceable corrections:** If a later data/identity refresh alters a previously archived team audit, its previous version is preserved under `revisions/`. Full prior period results are not silently lost.
7. **Exact calendar interpretation:** Fantrax's provider UTC-offset period end is compared against an aware current instant, not forced to midnight. Cross-league/season evidence cannot accidentally reconcile merely because period numbers match.
8. **Scout accuracy:** Narrative now describes numerical agreement rather than independently verified game credits. Generic missing-attribution boilerplate is replaced with the actual number of discrepant teams and teams with unresolved ACTIVE identities.

## Acceptance rationale / regression controls

**Previously observed Studio acceptance for v55:** 280/287 period roster identities matched; 13/14 team totals numerically matched; Justin's Fighting Capybaras 30/30; Waterbury Wolverines 36 identified vs 38 Fantrax (unexplained 2). These are historical observations, not a claim of v56 Studio results.

**v56 local tests:** 115 pytest tests, 36 unittest subtests passed. New tests cover (a) arbitrary teams and periods rather than Justin-specific mappings, (b) exclusion of bench/IR NHL scores, (c) numerical matches with unresolved identities, (d) exact source identity/period checks, (e) missing standings baseline and missing precise date boundaries, (f) historical alias resolution and name collisions, (g) retained audit revisions, (h) multi-season candidate fetch validation, (i) per-period archival identity inventories, and (j) exact timestamp period closure.

**Live acceptance after Sync League:**

- Inspect `Output/player_identity_coverage.json` for current and historical unresolved ACTIVE IDs; verify that statuses and names reflect authoritative source evidence. Zero coverage exceptions should not be manufactured merely to satisfy a KPI.
- Inspect `Output/PeriodScoringAudit/sync_manifest.json` across all selected completed periods. All 14 team rows should appear for each complete evidence set; unresolved teams must include named IDs/differences where available.
- Ask Scout to reconcile Week 3 again. Justin should remain 30/30 with no bench points included. Inspect Waterbury's remaining difference; do not assume the extra two points were resolved without player-level evidence.
- Repeat Week 2 and Week 3 and verify changing identity maps invalidates cached NHL period production. Source unavailable states and real roster changes must be preserved and disclosed.
- Do not claim point-by-point fantasy credit or the timestamp a manager moved a skater to ACTIVE unless the provider supplies a dated eligibility/lineup ledger. A historical roster snapshot and an exact team total alone cannot provide that proof.

## Deliberate boundaries

This overlay implements a **general system**: it contains no hardcoded Justin/Waterbury names, team IDs, game points, or exceptions. The official NHL stats endpoint and Fantrax authenticated historical evidence remain upstream dependencies. This is an engine foundation milestone, not a promise that the outstanding Waterbury two points disappear without subsequent live data or date-effective roster evidence.
