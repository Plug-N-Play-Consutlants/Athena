# v0.7.10.67.13 — NHL Adaptive Pagination

## Windows acceptance evidence
Refresh & Reconcile Evidence ran successfully as a Studio operation for completed periods 6, 7, 8 but returned `source_unavailable` with `NHL game summary pagination returned an incomplete page` for each period. This means the v67.12 network client reached pagination and encountered a page shorter than the requested width; it does not prove upstream data absence.

## Correction
- In `fetch_complete_nhl_game_summary`, pagination now advances `start` by **the number of rows actually received**, not by a hard-coded requested page size (500). A nonempty short page is allowed when its rows are complete, nonoverlapping, and the provider's total count remains consistent.
- The maximum number of result rows (15,000 by default) and paginated network requests (200) remain bounded.
- An empty page, changed total/schema, duplicate player/game or extra rows fails closed. Only exactly `total` rows can enter the window normalizer and historical cache.
- A final-page request is bounded to the remaining count.
- This correction does not claim to validate actual Fantasy credited points, game-effective lineup eligibility, or Period 8 source recovery.

## Tests
- New regression cases simulate upstream page limits of 100 and 23 even when 500 is requested, and verify actual-offset progression and complete coverage.
- 77 related regression tests and 6 subtests pass, including earlier fail-closed scenarios and Studio controls.
