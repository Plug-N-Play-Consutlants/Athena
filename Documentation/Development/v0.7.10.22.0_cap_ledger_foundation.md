# v0.7.10.22.0: Canonical cap ledger foundation

## Source findings

- `Knowledge/Packs/NHL/contracts/canonical_contracts.json` explicitly declares itself an illustrative, incomplete contract fixture, not an NHL-wide ledger.
- `Knowledge/Teams/team_economic_state.py` reads a static team-state pack; it does not acquire a current roster/contract ledger.
- `Providers/NHL/capabilities.py` exposes NHL roster/statistics acquisition, but no NHL-wide contract/cap adjustment acquisition.
- `Reasoning/Cap/cap_reasoning.py` previously accepted an injected `verified_cap_charge_total`; no existing production ledger computed it.
- `Reasoning/Transactions/scenario_engine.py` depends on that verified baseline, so current team scenarios remain numerically incomplete.
- Existing cap validation proves refusal to infer from incomplete inputs and tests synthetic complete totals. It does not validate a live NHL club's cap figure.

## Implementation scope

Added `Reasoning/Cap/canonical_ledger.py` to represent provenance-bearing effective-dated cap-charge entries, enforce domain-level completeness, compute a verified sum only for fully reconciled ledgers, and compare to a published independent total without silently overwriting evidence. `evaluate_team_cap_state` can accept such a canonical ledger while preserving its existing incomplete-ledger behavior. LTIR relief remains separate from ordinary headroom and is **not** assumed from a player's contract AAV.

## Outstanding release-blocking work

Do not represent it as production cap intelligence. Next integrate provider-compliant source acquisition, identity/roster reconciliation, effective-dated CBA accounting, persistence, provider discrepancy tracing, and Scout multi-objective synthesis.
