# AthenaEngine v0.7.10.63.2 — Studio listener discovery and launch correction

## Evidence from November 11 diagnostics

Studio saw an old v0.7.10.60.0 server at 127.0.0.1:8765, while the Windows-only stop helper reported zero listening PIDs and Studio blocked launch. Separately, Scout's session export identified v0.7.10.63.1 requests from F:\Development\AthenaEngine. Accordingly, export provenance does not establish which version occupies port 8765.

## Corrections

- Stop helper enumerates IPv4 AND IPv6 TCP listeners using unfiltered `netstat -ano`; independently falls back to Windows `Get-NetTCPConnection` when necessary.
- Listener parsing reads local TCP endpoint, listening state, and numeric PID. Active established connections are not considered listeners.
- When Scout is reachable but no process PID can be identified, stop fails visibly instead of reporting success.
- Before termination, verifies the listener is Scout from the target repository AND the OS process command line points to that repository. No unrelated service may be terminated.
- Studio browser URL and canonical Scout host use 127.0.0.1 to avoid differing localhost IPv4/IPv6 resolution.
- Keeps v63.1 launch identity gate intact.

## Validation

Focused local tests: 8 passed. Release hygiene: PASS. Windows runtime is not available in the build environment, so the actual listener cleanup must be checked under Studio on Windows. If the stop helper cannot verify a PID, it will refuse to stop it and report the block.
