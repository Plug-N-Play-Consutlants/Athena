# v0.7.10.67.3 — Scout runtime lifecycle reliability

## Regression
Studio launched Scout using a relative `launch.py` command with cwd set to the repository. Windows Win32_Process.CommandLine does not contain cwd. The stop helper demanded the repository path be present in CommandLine, so it refused to stop a valid Scout server although the HTTP /api/version root was verified. The refusal left port 8765 occupied and blocked reload.

## Correction
- Studio now launches scripts using absolute paths, so new Scout processes expose repository identity in Windows process metadata.
- The Windows Scout stopper accepts older relative-launch processes ONLY after both the HTTP listener and OS process identify the same PID, executable, and repository, with an explicit Athena Scout launcher argument.
- Unrelated processes, unknown scripts, missing provenance, mismatched root/PID/executable and unidentified listeners remain protected from termination.
- No broad taskkill-by-port, process-name sweep, or bypass of ownership verification was introduced.

## Acceptance on Windows
1. Apply overlay; use Studio Stop Scout while the previous v67.2/67.1 process is on port 8765. Confirm it stops successfully without closing Studio/browser.
2. Reload Build then Launch Scout. Confirm v67.3 from `/api/version` and no stale port.
3. Stop Scout and launch again. Confirm both succeed, with no refusal.
4. Independently run a non-Athena HTTP process on a different Scout-range port and verify its PID is never killed.

## Verification
Seven deterministic lifecycle tests passed under Linux mocking Windows OS/API output. Live Windows process termination remains an acceptance requirement.
