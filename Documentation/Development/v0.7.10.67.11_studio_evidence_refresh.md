# v0.7.10.67.11 — Studio Evidence Refresh Integration

## Purpose

Expose the existing `Tools/diagnose_period_evidence.py` acquisition/reconciliation workflow in the existing Athena Studio Core Workflow, without coupling it to Verify Build.

## Changes

- Core Workflow: **Refresh & Reconcile Evidence** beside **Sync League**, replacing the previous **Review Shims/Duplicates** shortcut.
- The prior repository review handler remains available under **Developer Diagnostics**.
- Select 1–8 distinct completed periods (default `6 7 8`). Studio launches the existing CLI with `--periods ... --refresh` using the current interpreter and configured workspace.
- Run asynchronously through Studio's established command runner. Studio writes a full command log and history; the console summarizes the acquisition manifest and per-period missing sources, numerical matches, differences and unresolved player identities.
- Canceled/invalid period input cannot launch a refresh.
- This is independent of Verify Build. The standalone CLI remains available for headless operations.

## Evidence caveats

- Successful command execution does not prove successful source acquisition. Period statuses and acquisition blockers are explicit in the Studio summary.
- Numerically matching NHL G+A and period team points does not prove game-effective credited fantasy points.
- Requires authenticated Windows/league environment for real acquisition; local tests verify Studio dispatch and presentation, not live provider access.
- Existing historical acquisition and revision safeguards are unchanged.
- The generic Studio command launcher does not yet support mid-run cancellation or a detailed progress bar.

## Tests

`Tests/test_studio_evidence_07106711.py` includes five focused cases covering period selection, dispatch, cancel, partial coverage and malformed output. The surrounding historical-evidence, transaction and Studio regression set passed locally.
