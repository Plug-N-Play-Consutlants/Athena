# v0.7.10.67.21 — Scout Lifecycle Integrity

Focused lifecycle hotfix on top of cumulative v67.20.

- Restart Studio now invokes the same verified Scout shutdown helper as Reload Build and refuses relaunch if shutdown cannot be verified.
- Reload Build aborts on any nonzero stop-helper status or occupied Scout listener port; it does not purge caches or schedule a new instance after failed shutdown.
- Force Launch Scout similarly aborts on nonzero stop-helper status, rather than relying only on port observation.
- Verified Scout PID termination uses Windows `taskkill /T /F` to close launcher descendants, never unrelated servers.
- A missing stop helper is an explicit failure rather than success.

The installed Windows lifecycle still requires live acceptance: independently inspect listener PIDs, use Stop Scout/Reload Build/Restart Studio, confirm old PIDs have exited and one new Scout instance is serving expected version. Do not assume a version string alone proves a terminated process.

The v67.20 targeted trade query returned `No canonical trade matches` in live Scout. Transaction acquisition and direct query routing remain open defects outside this narrow lifecycle hotfix.
