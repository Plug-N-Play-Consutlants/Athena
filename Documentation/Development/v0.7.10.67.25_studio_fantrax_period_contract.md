# v0.7.10.67.25 — Fantrax Period Contract Studio Diagnostics

## Scope

Studio's Core Workflow now includes **Fantrax Period**. It opens a read-only diagnostic panel with season start-year and scoring-period fields, a **Run Probe** action, and **View Report**. The diagnostic executes the existing authenticated `Tools/fantrax_period_probe.py` script inside Studio, stores only schema metadata under `Output/fantrax_period_probe_YYYY_pNN.json`, and shows the stored JSON without a PowerShell workflow.

Studio remains the normal operational UI; command-line execution remains an optional engineering fallback. Invalid season/period inputs are rejected before constructing paths. Studio's **Reload Build** remains stop-only: this build does not change Scout process lifecycle.

## Evidence and remaining blocker

The received 2026 Period 8 probe (v67.24) confirms `SEASON_31n_BY_PERIOD`, the `fpts` and `fptsPerGame` columns, and 500 returned rows. **It does not confirm specific period 8 selection**. The selected response's schema is the same as the initial response, and no provider-confirmed period-selection field or response period identity is present.

The probe now includes an explicit `contract_comparison` indicating that the season-level selector was sent but **no verified individual-period parameter was transmitted**, the response does **not** prove period identity, and ledger writes remain disabled. This is diagnostic information, not a claim that the Fantrax period contract has been resolved.

## Acceptance boundary
