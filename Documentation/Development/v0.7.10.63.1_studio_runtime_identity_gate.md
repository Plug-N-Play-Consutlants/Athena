# v0.7.10.63.1 — Studio / Scout Runtime Identity Gate

Scoped corrective overlay on top of v0.7.10.63.0. Does **not** rebuild player data or change Aho identity logic.

## Observed failure

Studio accepted any TCP listener on port 8765 as successful Scout startup and could open that server's page even when Studio loaded newer repository code. `Core/version.py` within v63.0 is set correctly. A user-facing `Scout v0.7.10.60.0` means a server from that version answered, or the expected files were not installed at the served repository root; neither case should be silently accepted.

## Change

- Studio reads the running `/api/version` response, compares live `scout_version` and normalized `project_root` against its installed `Core/version.py` and canonical directory, and records observed live version/path/PID.
- Launch/Reload Build cannot claim success or open the browser based on an occupied TCP port alone.
- Reload refuses to spawn another server when a stop fails or Scout-range ports remain occupied.
- Windows stop helper verifies that a Scout HTTP listener belongs to **this repository** before killing any PID. Unverified/unrelated services cannot be killed by this helper.
- Five focused identity-gate tests cover correct version/root, stale version, different root, unknown listener, and unsafe stop rejection.

## Acceptance and limitations

1. Apply over v63.0 in the same AthenaEngine root that launches Studio.
2. Relaunch Studio (to load the updated Studio code), then use Reload Build.
3. Studio must report `Scout version AND repository verified on port 8765` before opening Scout.
4. If mismatch, Studio shows the actual vs expected version and served root in its console, does not open the old page, and does not claim a pass. This diagnostic alone cannot modify a different source tree or forcibly kill another repository's server.
5. After the version is verified, retest Carolina and Swedish Aho full-profile routing. If these remain short profiles under verified v63.1, that is a separate route/logic defect rather than a launch-version ambiguity.

Offline validation: 10 tests passed in integration+runtime-gate suite; release hygiene PASS; Studio reload workflow PASS. Windows live runtime testing not available in this environment.
