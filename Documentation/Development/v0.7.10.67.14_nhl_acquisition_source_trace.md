# v0.7.10.67.14 — NHL Source Trace

## Motivation
The live Studio refresh for v67.12 returned the same pagination failure for scoring periods 6, 7 and 8. v67.13 changed pagination offsets to advance by received row count, but no subsequent live NHL response has been supplied. More speculation-based pagination changes would be premature.

## Change
- NHL game-summary acquisition now optionally records sanitized request/response-shape metadata (requested offsets and limits; returned row count; declared total; schema validity).
- On a rejected NHL fetch, `acquire_nhl_period_production` saves a bounded diagnostics file under `Output/PeriodScoringAudit/nhl_source_traces/<league>/<season>/period_NNN.json` and attaches its relative path to the acquisition blocker.
- No raw player rows, user credentials, request URLs or Cayenne filters are stored in this trace.
- Historical scoring evidence remains unverified and no production cache is written if NHL acquisition fails. Existing source-completeness constraints remain unchanged.
- The new trace can be inspected via Studio's existing command log or diagnostic archive. No extra Studio button is required.

## Acceptance
Install overlay, restart Studio, run `Refresh & Reconcile Evidence` for periods 6, 7, 8 and export the diagnostics if a blocker remains. The saved source trace will show whether the service returns empty, incomplete, short or inconsistent pages. Do not interpret a successful process exit as verified historical evidence.

## Tests
34 targeted regression tests and 6 subtests passed. In a separate wider selection, six failures appeared in existing Studio tests that patch removed `urllib` internals or instantiate AthenaStudio without `_verify_active`; these are not caused by the NHL trace changes and are not claimed fixed.
