# AthenaEngine v0.7.10.53.0 — Consolidated Period & Player Intelligence

## Why this release is not another micro-diagnostic

Three paths are revised together: Fantrax league-type semantics; authoritative NHL
skater game-level acquisition and boundary verification; and Scout's actual weekly
player narrative. The previous v0.7.10.52.1 transaction-dashboard fix is included.

## Root causes established from actual JHLPAA configuration

- `Raw/league_info.json` states `scoringSystem.type=POINTS_BASED`. Fantrax documents
  `scoringPeriods` for head-to-head leagues. JHLPAA has `rosterPeriods` instead;
  absence of head-to-head `scoringPeriods` is not a provider failure.
- Period 3 is exactly 2026-10-12 13:00 EDT through 2026-10-19 18:59:59 EDT.
  Midnight/midnight, Monday/Sunday and rolling-seven-day substitutions are wrong.
- Fantrax authenticated `getPlayerStats` returned schema and `SEASON_31n_BY_PERIOD`
  selector but not evidence of the concrete period; previous strict gate stays.
- `Output/player_identity_map.json` resolves 227/287 currently rostered Fantrax
  IDs to NHL identities in the supplied snapshot. Some assets cannot be linked
  with evidence; never invent missing identities.
- `Output/transaction_master.json` and `transaction_history.json` contain 35
  canonical records. The raw feed has zero normalized rows; dashboard now
  distinguishes these facts without declaring absence of transactions.

## Implemented

1. Recognize `POINTS_BASED` roster/reporting periods without inventing scoring
   periods, retain exact provider offset-aware start and end instants.
2. Pull NHL game-granular `skater/summary` for the exact date span, plus official
   schedule records to check boundary-day puck-drop instants; exclude next-week
   games after the cutoff and reject unsupported/partial/duplicate records.
3. Join only verified Fantrax-to-NHL player IDs. Score NHL goals plus assists,
   distinguish **NHL production** from **Fantrax credited points**, and label
   current-roster attribution as *not verified historical ownership/eligibility*.
4. Cache successful closed-window evidence for twelve hours, keyed by league,
   season, period and exact timestamp bounds. No individual-player HTTP fanout.
5. Scout now includes an “Individual NHL performances (matched players)” segment
   with scoring leaders when the public NHL response passes validation.
6. Keep trading blocks out of required period evidence: stale advertisements
   are marketplace context, not weekly scoring facts.

- `python -m pytest -q Tests`: **69 passed, 36 subtests passed** using the

- New `Tests/test_points_based_player_reporting_0710530.py` covers period type,

## Acceptance — one integrated Studio/Scout pass

1. Extract overlay into repository root and reload Studio.
2. Sync league, run existing Studio verification.
3. Ask Scout, in Public or Fantasy: “Produce the JHLPAA weekly league report for
   the most recently completed reporting period, including NHL individual
   performances, trades, standings and what remains unverified.”
4. Expected: Week 3 calendar provenance states points-based roster/reporting;
   trade dashboard reconciles 35 history records; standings and trades remain;
   NHL player leaders appear if public NHL sources respond and validate.
5. If player leaders remain absent, inspect the `provider.nhl.period_game_production`
   trace and bounded `source_unverified`/`source_unavailable` diagnostic once.
   Do not create another incremental field probe; capture the provider response
   schema in one consolidated fixture-based correction.

## Explicitly outside this release

- Historical period-effective lineups/keeper status. Requires authenticated
  Fantrax historical roster acquisition and lock/effective policy verification.
- Fantrax-specific credited player fantasy points. NHL G+A alone cannot establish
  fantasy team points if a skater was benched, injured, traded, or added mid-period.
- Historical draft-asset ownership chains and trading-block advertisements;
  both are lower priority than complete performance/lineup attribution.
- A final/live Studio PASS or a lock of the entire evidence-integrity milestone.
