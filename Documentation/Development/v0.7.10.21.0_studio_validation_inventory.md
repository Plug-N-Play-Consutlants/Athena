# Athena Studio validation inventory — v0.7.10.21.0

## Scope and policy

Studio keeps the existing interface and actions. **Verify Build** now runs one curated release registry; the separate **Validate Everything**, **Doctor Everything**, **Studio Validate**, and **Studio Doctor** actions remain available for extended and focused checks. No buttons were added.

The release gate emphasizes current execution ownership and supported capabilities. Historical or maintenance checks that remain useful are retained in extended workflows rather than repeated on every build. A registered command with a missing script is a failure, not a successful skip. Failed commands show a short error summary and keep their complete output in the command log.

## Consolidation and disposition

| Finding | Disposition | Rationale |
|---|---|---|
| Previous 110-command Verify Build mixed build checks, doctors and extended implementation-era checks | Consolidated | The release gate now has 17 checks. From the previous target set, 12 remain in the gate, 96 remain in the extended validator/doctor workflows, and 2 redundant acceptance-doctor wrappers leave aggregate execution. Five current-path regressions were added. |
| Epic 4 and Scout acceptance doctor wrappers duplicated their validator suites | Retired from aggregates; scripts retained for manual compatibility | Their validators remain release-critical and exercise actual runtime behavior. The wrappers are not invoked redundantly by Doctor Everything or Verify Build. Cleanup reports these wrapper files as review-only; it never deletes them. |
| Professional, historical, and Scout response checks risked falling out of all aggregate workflows during curation | Retained in Build or Validate Everything | The professional-player pathway is a targeted Build regression. Historical draft, league, identity, pre-draft, public-team-news, player-assessment, Scout composition and application-trace validators remain in Validate Everything. |
| Historical Studio phase/PIF fallback targets could silently select obsolete suites | Retired | Studio validation now selects Phase 2 and PIF Build 004 only. Missing current targets fail rather than falling back to prior phases or being skipped. |
| `Tests/validate_studio_polish_repository.py` is not registered in a current aggregate workflow | Retired from active registration; file retained | Its assertions require a “Validate Studio Polish” control and self-registration that are not part of the supported interface. Current version/release checks, Studio operations-console coverage and repository health diagnostics cover its useful behavior without adding a control. |
| Cleanup validator required safe-cleanup checks in Verify Build | Corrected | Safe-cleanup validation and doctor remain in their extended maintenance workflows; the release gate checks release readiness and engine capability behavior. Cleanup treats the two retired wrappers as review-only artifacts and preserves safe-deletion protections. |
| Missing scripts were printed as `[SKIP]` without failing a sequence | Corrected | A missing registered validation target now emits `[FAIL]`, increments failures and fails the overall sequence. |
| Failure reporting exposed full command output in the console | Consolidated | Console summaries now prioritize `[FAIL]`, exceptions and assertion errors, cap detail length, and point to the complete persisted log. |

All 64 extended validators, 44 extended doctors, and both seven-command Studio-specific suites resolved to existing targets when the registry was enumerated. Each aggregate has unique targets. Cross-workflow overlap is deliberate so Studio users can run either broad validation or focused Studio checks independently.

This inventory describes headless registry coverage, not GUI Studio acceptance or live-provider testing. Final release acceptance still requires Studio Verify Build and relevant Scout runtime verification in the supported Studio workflow.
